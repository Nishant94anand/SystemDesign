# System Design Interview Checklist

Use this for timed practice, not as a substitute for [Syllabus V2](../curriculum/SYLLABUS_V2.md) or the [exercise template](../design-exercises/TEMPLATE.md).

- [ ] Clarify users, functional requirements, scope and non-goals.
- [ ] Define measurable NFRs and conflicting priorities.
- [ ] Estimate average/peak traffic, storage, bandwidth, growth and headroom.
- [ ] Define API contracts, workflows, data model and access patterns.
- [ ] Draw architecture and trace the critical request/data path.
- [ ] Justify storage, cache, queue, partitioning and replication.
- [ ] State invariants; analyze concurrency, retries and partial failure.
- [ ] Identify bottlenecks, hot keys, overload and graceful degradation.
- [ ] Cover security, observability and operational ownership proportionately.
- [ ] Compare alternatives, costs, complexity and invalidating assumptions.
- [ ] Summarize trade-offs, risks and evidence that would change the design.

Track production/Principal-level gaps separately in progress/PROGRESS.md.
