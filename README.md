# System Design Learning Lab

A Markdown-first, interactive learning workspace for Staff/Principal-level system design intuition, interview readiness, production judgment and technical leadership.

## Start here
1. Read [Project Instructions](CopilotInstructions/PROJECT_INSTRUCTIONS.md) for persistent tutoring rules.
2. Use [Syllabus V2](curriculum/SYLLABUS_V2.md) as the canonical curriculum. [Syllabus](curriculum/SYLLABUS.md) is the short entry point.
3. Read the [Detailed Playbook](docs/LEARNING_LAB_PLAYBOOK.md) for session, exercise, assessment and publishing rules.
4. Resume from [Progress](progress/PROGRESS.md); it records demonstrated evidence, not assumptions.
5. Start a design with [the exercise template](design-exercises/TEMPLATE.md); browse [exercise cases](design-exercises/README.md).
6. Browse [Concepts](concepts/README.md), [Research](research/README.md), [Resources](resources/README.md), [Revision](revision/README.md), and [Architecture Decision Records](architecture-decisions/README.md).

## Starter prompt
> Chalo bhai, System Design Learning Lab continue karte hain. Syllabus V2 aur latest Progress ko grounding source banao. Friendly Hinglish mein intuition se precise technical details, trade-offs aur failure modes tak jao. Ek baar mein ek meaningful question poochho. Exercise ka full solution tab tak mat dena jab tak main try na kar loon, unless main directly solution/reference notes maangoon. End mein demonstrated evidence, gaps, readiness aur next step record karna.

## Source-of-truth rules
- Project Instructions: persistent behaviour and learning protocol.
- Syllabus V2: curriculum scope, sequence, exit evidence, scorecards and change policy.
- Playbook: teaching workflow, readiness labels and publishing standards.
- Progress: learner-specific state and next action.
- Concept chapters and exercises: canonical technical explanations and applied evidence; link rather than duplicate.
- If sources conflict, call out the conflict and propose the smallest relevant correction. Do not silently rewrite unrelated instructions.

## Documentation conventions
- Markdown by default; Mermaid where useful.
- Keep chapters modular and use relative links.
- Distinguish verified facts, assumptions, simplified models and open questions.
- Verify current vendor-specific guarantees, limits and pricing against official sources.
- Never claim a file or external system changed unless the operation succeeded.
