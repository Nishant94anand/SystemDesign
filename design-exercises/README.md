# Design Labs

The learning order is defined by the [Progress Topics table](../progress/PROGRESS.md). The files in `cases/` are problem prompts only, not solutions.

On completion, create a topic folder under `design-exercises/` with a complete design document based on [TEMPLATE.md](TEMPLATE.md). Add diagrams, decisions, trade-offs, failure scenarios, operations, security and references as relevant. Do not create empty final-artifact folders or pre-write the design before the discussion.

## Capstones in the ordered learning path

- [Integrated Commerce and Inventory](cases/integrated-commerce-capstone.md) — Phase 3; combine NFRs, estimates, inventory invariants, payment ambiguity, asynchronous workflows, failures, and design evolution.
- [Principal Legacy SaaS Modernization](cases/principal-modernization-capstone.md) — Phase 5; multiple teams, tenant isolation, ADR, strategic alternatives, migration, cost, rollout and recovery decisions.

The [Progress Topics table](../progress/PROGRESS.md) is authoritative for status and order. These files are **solution-free prompts**, not completed submissions. On user-confirmed `COMPLETE TOPIC`, follow the [Learning Workflow](../CopilotInstructions/LEARNING_WORKFLOW.md) and [Playbook](../docs/LEARNING_LAB_PLAYBOOK.md) to publish a full design with original Mermaid diagrams, comparisons, formulas or visual aids where useful, then verify artifact links before marking COMPLETED.
